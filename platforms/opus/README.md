# BLOODMOON for Opus 2

BLOODMOON as a plugin for **[Opus 2](https://github.com/LizardMan245/opus)**, LizardMan's plugin manager for the
original OP-1 (firmware 246). It is the same dark organ and haunted bell as v1.3 (computed at half rate since 1.5.2), with the same
moon-and-cathedral screen, rebuilt on Opus's own plugin kit so it loads as a native `.opmod` file. You don't need the Hundekraft Workshop
or Opus's op1r bridge for it.

> **Status: checked on a computer and a Blackfin simulator only.** 1.5.0 and 1.5.1 were switched off for their CPU
> on a real OP-1; 1.5.2 fixes that but has not been tried on one yet. Opus 2 itself is a beta. Please report what you
> see and hear, and the "audio: worst" number (see CPU below).

## What you need

- An original OP-1 (not the Field) with **Opus 2** installed: core **2.6 or newer** (beta 3 has core 2.13). You make
  the Opus update from your own firmware with the patcher at https://opus-op1.pages.dev/patcher/.
- `bloodmoon.opmod`: in [the download zip](../../download/bloodmoon-1.5.2.zip) (`opus/bloodmoon.opmod`), or on its own in
  [`download/opus/`](../../download/opus/).

## Install

1. **Developer mode** (only for the first tries): hold **synth + drum + tape + mixer** for Opus's menu, then **T1**
   (system), and switch **developer mode** on. While it is on, Opus shows you what the plugin really does instead of
   leaving it out after a crash.
2. **Disk mode:** **shift + COM**, then **T3**, and connect the OP-1 to your computer.
3. Copy `bloodmoon.opmod` into the disk's **mods** folder. Eject the disk, then switch the OP-1 off and on.
4. Open Opus's menu again and press **T2** for the mods list. Turn **blue** to **bloodmoon**: the row should say
   **loaded**. If it shows a reason instead, please send it to us.
5. On a synth slot, press **shift + T1** and choose **bloodmoon** from the engine list. Start with the volume low.

**If something goes wrong:** hold **Stop** while you switch the OP-1 on. It starts with no plugins at all, so you can
delete `bloodmoon.opmod` from the mods folder in disk mode. Opus never touches te-boot, so you can always reinstall
(hold **COM** while you switch on).

## The knobs and the screen

These are the same as v1.3. See the main [README](../../README.md) for what each knob does and how the screen follows it.
BLOODMOON takes no keys or shifted encoders. The OS's encoders turn its four knobs on T1, and T2 is the OS's
envelope, as before.

## What is different from the op1r version

- **Presets: probably not yet.** The engine claims op1r's sound type `bloodmoon`, which the kit says makes op1r
  sounds load as this engine. Opus's author has said such sounds do not load, so the presets in `presets/bloodmoon/`
  are probably Hundekraft and op1r only. Opus presets need the format Opus saves (`iter`, a number in knob 4, an
  `"opus"` member), read from one bloodmoon sound saved on an OP-1.
- **Don't load both.** If you also put `bloodmoon.op1p` in front of Opus's bridge, the two claim the same type, and
  Opus refuses the one that loads later.
- **Velocity is applied once.** Under Opus the OS scales each voice by velocity. The op1r build also scaled by it
  inside the engine, so soft notes come out a little louder here.
- **Half rate.** Since 1.5.2 the voice is computed at 44.1 kHz with its LFOs once a block, to fit the OP-1's
  processor. Every note stays within 1 dB of v1.3; the highest notes lose up to 0.8 dB of their top harmonics.
- **LFO.** The knobs reach the engine with the OS's LFO already in them, so the T4 LFO can now move BLOOD, ECLIPSE,
  HAUNTING and MOONRISE.
- **CPU.** 1.5.0 and 1.5.1 were switched off on the device ("over its CPU"). On GDB's Blackfin simulator 1.5.1's six
  voices took 247,335 cycles a block and 1.5.2's take 68,207 (`tests/bench_bfin.sh`). The figure in
  `noladrift.bloodmoon/cpu.txt` is a provisional 120,000 until it is measured on a device: developer mode on,
  six-voice chords with every knob up, then read "audio: worst N" from its details (**orange** push on its row) and
  put `cycles N` in `cpu.txt`.

## How it is built

| File | What |
|---|---|
| `src/noladrift.bloodmoon/manifest.txt` | The plugin's id (`noladrift.bloodmoon`), version and the core it needs |
| `src/noladrift.bloodmoon/cpu.txt` | The CPU figure the build writes into the manifest (provisional until measured on a device) |
| `src/noladrift.bloodmoon/bloodmoon.c` | The engine: v1.3's sound on Opus's `struct opus_engine`, plus `opl_init` |
| `src/noladrift.bloodmoon/moon.c` | The T1 screen: v1.3's moon, bells, rose window, stars and digits, using the kit's named firmware calls |
| `src/noladrift.bloodmoon/bm_sine.h`, `bm_art.h` | Generated by `make_headers.py`: the sine table, and the OP-1 build's `bloodmoon.svg` (the one copy of the art) as a C string |
| `tests/compare.c`, `tests/run.sh` | Computer test: the port against v1.3, sound and screen (`SANITIZE=...` adds sanitizers) |
| `tests/bench_bfin.c`, `tests/bench_bfin.sh` | Cycle benchmark on GDB's Blackfin simulator, optionally beside an older revision |

The released `.opmod` in `download/` (1.5.2) was built on GitHub from commit `67ff2f4` with the kit's own compiler
script and the Opus kit at commit `d9b0d2e`. You only need what follows if you change the source.

To build it yourself, follow the kit's
[getting started](https://github.com/LizardMan245/opus/blob/main/plugin-kit/docs/getting-started.md) for the
compiler, then:

```
OPUS_KIT=path/to/opus OP1_BFIN_TOOLCHAIN=path/to/toolchain tools/build-platform/build-opus.sh
```

That writes `build/opus/bloodmoon.opmod`, apart from the released file. Without a local compiler, run the manual
**Build Opus plugin** workflow in GitHub's Actions tab: it builds the file, measures it on the simulator, says whether
it equals the released one, and attaches it to the run.

## Validate

```
OPUS_SDK=path/to/opus/plugin-kit/sdk platforms/opus/tests/run.sh          # against v1.3, sound and screen
SANITIZE="-fsanitize=address,undefined -fno-sanitize-recover=all" OPUS_SDK=... platforms/opus/tests/run.sh
OPUS_SDK=... OP1_BFIN_TOOLCHAIN=... platforms/opus/tests/bench_bfin.sh 801f8a7   # cycles, beside 1.5.1 (needs bfin-elf-run)
python3 tools/preset-validation/validate_presets.py --render              # the op1r/Hundekraft presets
```

## Limitations

- Not yet confirmed on a real OP-1; the CPU figure is provisional.
- The highest notes lose up to 0.8 dB of their top harmonics (half-rate computation).
- No Opus presets yet (see above).
- Do not load it beside op1r's `bloodmoon.op1p` through Opus's bridge: both claim the same sound type.
